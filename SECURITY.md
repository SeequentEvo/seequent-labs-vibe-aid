# Security Policy

## Reporting a vulnerability

Please report suspected vulnerabilities privately. Do not open a public GitHub issue for security-sensitive details.

Use GitHub's **Private vulnerability reporting** for this repository (the Security tab → Report a vulnerability). If private reporting is unavailable for your deployment, contact the repository maintainers through the private channel listed in the repository administration page and do not post the report publicly.

Include:

- Affected component and version/commit
- Reproduction steps or proof of concept
- Impact assessment
- Suggested remediation, if known

We will acknowledge reports, assess severity, coordinate a fix and disclosure timeline, and keep the reporter informed.

## Supported versions

Only the current `main`/default branch and the most recent released deployment are supported for security fixes unless otherwise stated.

## Public issue policy

Public Issues may be used for non-sensitive bugs and feature requests. Security reports must be handled privately until coordinated disclosure is complete.
